## 이후 백엔드 연결 작업 원칙

1. 프론트 문구와 화면 흐름을 임의로 바꾸지 않는다.
2. 질문/결과/점수 계산 데이터는 `src/data/coolbti.ts` 기준을 유지한다.
3. `/admin` UI는 데이터 조회/수정/삭제 연결만 보강한다.
4. Supabase `service_role` key는 Vercel 서버리스 API 환경변수에만 넣는다.
5. `VITE_` 환경변수에는 공개 가능한 anon key와 URL만 넣는다.
6. 기존 `main`은 Streamlit 앱 히스토리이므로, 별도 승인 없이 force push하지 않는다.

## 현재 백엔드 연결 구조

- `api/results.js`
  - `POST /api/results`: 퀴즈 결과를 `coolbti_results`에 저장하고 `id`, `public_slug`, `client_token`을 반환한다.
  - `PATCH /api/results`: `id` + `client_token`으로 식물학생증 입력값(`user_nickname`, `plant_name`, `user_intro`)과 `card_payload.studentCard`를 업데이트한다.
  - 이 API는 Vercel 서버리스에서 `SUPABASE_SERVICE_ROLE_KEY`를 사용한다.

- `api/admin/results.js`
  - `GET /api/admin/results`: 관리자 조회
  - `PATCH /api/admin/results`: 관리자 수정
  - `DELETE /api/admin/results`: 관리자 삭제
  - 관리자 요청은 `x-admin-token` 헤더로 보호한다.

- 프론트 저장 흐름
  1. 결과 화면 진입 시 `POST /api/results`로 결과 row 생성
  2. Vercel API가 없거나 환경변수가 없으면 기존 anon Supabase insert로 fallback
  3. 식물학생증 저장 시 `PATCH /api/results`로 같은 row에 학생증 입력값 저장

주의: Vite 로컬 dev 서버만 단독으로 켜면 `/api/results`가 없으므로 fallback 경로로 동작한다. Vercel 배포 또는 `vercel dev`에서는 서버리스 API까지 같이 확인할 수 있다.

## DB 스키마 주의

`api/results.js`가 정상 작동하려면 `coolbti_results`에 아래 컬럼이 있어야 한다.

```sql
client_token text not null unique default encode(gen_random_bytes(16), 'hex')
user_intro text
```

기존 Supabase 프로젝트가 이미 만들어져 있다면 `docs/supabase-schema.sql`을 다시 실행해서 누락 컬럼과 grant를 보강한다.

## Vercel 배포 기준

현재 최신 축제 앱은 `codex/festival-coolbti` 브랜치에 있다.

Vercel에서 최신 화면이 안 보이면 먼저 확인할 것:

1. Project `festival-coolbti`
2. Settings -> Git
3. Production Branch가 `codex/festival-coolbti`인지 확인
4. Build Command: `npm run build`
5. Output Directory: `dist`
6. Install Command: `npm install`

`main`을 production으로 쓰려면 기존 Streamlit main을 덮어쓰는 작업이므로 별도 명시 승인이 필요하다.
